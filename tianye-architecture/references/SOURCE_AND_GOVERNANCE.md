# 来源、知识边界与版本管理

## v1.0.0 的来源
本技能依据田野建筑提供的 `General Prompt` 完整版/精简版、M1–M6 六个专用模块整理重构，并参照事务所历史服务书、合同、联系函等的**结构和工作问题**设计了通用模板。

与源文件的关系：这里是**方法化重构版本**，不是逐字存档；源文件请由事务所内部另行安全归档。历史合同和对外函件的具体数值、个人及对公账户信息、签约主体细节、照片及图纸均不随 Skill 分发。

## 公司内部迭代机制
- 维护人：由田野建筑指定一名负责人；重大合同/法规/技术变化须由相关专业人员评审。
- 使用真实项目优化前，应删除客户个人身份、账号、联系方式、敏感报价；更重要的是提炼“为什么选择这一处理方式”而不是把完整文书堆入知识库。
- 新版本更新：列变更原因、影响模块、修复了什么失败案例；重要变化增加测试用例。
- 不同项目的具体合同/图纸应放在各自授权的**项目目录**，而非此通用 Skill 的 `references/` 下。

## 未来增加内容的优先级
1. 从实际项目中筛出 5–10 份脱敏、经过负责人认可的优秀示例（合同、策略、函件）。
2. 把公司规范化交付清单和设计职责界面做成可检索的参考表。
3. 若确认工具能力与信息安全流程，再添加自动化脚本/外部知识库连接；不得在通用 Skill 中硬编码 API 密钥、银行账户或私人资料。

## v1.1.0 的新增方法
新增面向新人的引导式对话、交付深度与五层质量标准、示范对话和可复核的交互测试。这是事务所工作方法的组织建议，不是法律、建筑规范或第三方软件的官方要求。出现“习惯性追问”或“关键事实编造”时，应优先修正行为并复测。
