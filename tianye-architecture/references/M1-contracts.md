# M1｜合同 / 项目服务书 / 商务边界文件

**适用**：设计合同、服务书、服务范围/报价、合同审查、补充协议、额外工作确认、专业分工和阶段成果。

## 1. 识别文件和任务
区分合同、服务书、合同+服务书组合、修订/审查/比对。判断用户是要谈判文本、签约稿、内部风险审查，还是对客户的服务说明，不能一套文字通吃。

## 2. 项目事实检查表
逐项从现有材料提取，不存在就标 `[待确认]`：项目名称、地点、甲乙方、项目性质、面积/边界、服务阶段、工作深度、交付清单及格式、周期及起算、甲方资料和配合条件、费用/税费/付款条件、修改次数、阶段确认、第三方工作及专业界面、成果权属、额外工作触发条件、终止与争议约定。

特别留意“方案/扩初/施工图/专业深化/审图/施工配合”区分；建筑、结构、机电、幕墙、消防、专项设计及报批签章不应混写。“概念方案”不当然等于可施工成果。

## 3. 必须提出的专业判断
- 范围是不是过泛，“全程配合、包括但不限于”是否无上限？
- 服务成果是表述性承诺，还是可验收的图纸/文件/阶段？
- 工程技术和专项责任是否由具备职责及资质的一方承担？
- 付款节点是否被无期限审批、甲方单方满意或第三方结果绑死？
- 甲方未按期给出资料/反馈、设计反复返工如何处理？
- 新增范围、运营修改、尺寸基础数据错误、改造条件变化有无书面变更与计价规则？
- 设计方的现场服务频次、超出服务、异地差旅有无约束？

## 4. 输出流程
A. 概要提取（只列关键已知事实和缺口）
B. 主要风险按**高/中/低**排序，并指出与哪项事实/哪条合同相关
C. 建议采用的结构或修订点（必要时给对照条款）
D. 按用户需要提供可用合同/服务书/补充条款全文，保留占位符
E. 最后简短“风险复检”：范围、责任、成果、验收、付款、修改、配合、追加工作，未解决的标明

## 5. 特殊守则
- 不捏造条款编号或法律依据；无法核验的法律效力以“建议法务确认”处理。
- “3个工作日未回复视为默认确认”不作为通用规则或确定法律结论，必须看合同约定、通知送达证据及争议风险。
- 历史项目出现过“追加30%设计费”的商务谈判经验，**不是公司对所有项目的默认费率**；加价必须结合当期合同、实际新增工作量、双方书面确认。
- 以甲方/施工方提出“不必做钢结构/幕墙专项设计”等意见为例：先明确方案与技术深化各自责任、需由谁依据现行要求核验，不能未经审核作出“可以豁免”的安全判断。

## 新同事引导与交付深度（v1.1）
用户只说“帮我做合同/服务书”时，优先问用途（谈判/签约/内部审查）、设计阶段/专业分工、最担心的风险，而不是先索取所有项目信息。对用户不懂“扩初、施工图、专项深化”的情况，使用一句通俗说明差别。签约稿与内部审查稿的交付深度不同；有影响法律效力的缺口时应明确标出，不能冒充可直接签署。
