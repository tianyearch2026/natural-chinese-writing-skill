# M2｜项目分析 / Strategy / 提案与汇报

**适用**：机会评估、客户研究、业态定位、城市更新/不动产策略、项目概念、空间与运营协同、汇报逻辑、现有方案批判性修正。

## 1. 核心拆解
分清：客户明确诉求、背后经营焦虑、项目真实矛盾、不可更改的条件、可利用的资源、机会点、最薄弱的假设。不要把甲方需求原话装饰成策略。

典型现实变量：建筑原结构和柱网、消防疏散/机电条件、运营模式、资金和分期、预期营收、建设周期、审批路径、长期维护能力、目标客群/停留理由。

## 2. 三层论证（不能缺）
**判断层**：说明为什么该问题是核心、哪些证据支持、哪些数据只是推断。
**策略层**：主张什么定位与取舍、同质化方案的盲点是什么、做什么/不做什么、如何形成可验证的差异化。
**落地层**：分别提出策略动作、空间动作（动线、界面、节点、功能、材料、尺度）、产品/运营动作（业态、客群、经营、活动、维护）、沟通动作（甲方决策问题、需要确认的边界）。

## 3. 推荐处理步骤
- A 任务类型与资料质量判断（成熟/半成品/混乱）。
- B 用一句话概括项目真正矛盾；提供可证伪的判断依据。
- C 按重要性列出 2–4 个核心问题和取舍，而不是堆砌概念。
- D 提出最优路径（必要时 2 个情景方向），明确依赖条件及成本。
- E 给出汇报页大纲或正式提案内容，每页：**一句判断 + 一层展开 + 一层动作转译**。
- F 对重大提案附“反方质疑”：甲方最可能质疑的 3 点；竞争对手会攻击哪里；什么地方只是有审美但不足以支持投入。

## 4. 案例研究规则
每个案例写清：值得看的原因、方法机制、适用条件、不能照搬之处、如何转译为本项目可执行动作。不要罗列名词、设计师名称或未经核对的指标。

## 5. 交付形式
可根据需要输出：调研与假设表、议题树、决策矩阵、项目策略 brief、客户会议讨论提纲、PPT/Canva 页内容和讲述顺序。无真实数据时，不要假定收益率、客流量、造价或回报期，改为列所需数据和测算方法。

## 新同事引导与交付深度（v1.1）
模糊“帮我做项目报告”时先确定：给谁看、希望做什么决策、项目最难解决的一个矛盾及现有依据；随后由助手推荐内部策略稿或可对外汇报稿。引导用户思考“为什么要做、为什么现在做、如果不做会怎样、谁来运营”。需要图像/分析图时明确每张图证明什么。审美不是装饰，应服务设计论证；项目没有的桥、道路、建筑和数据不得虚构。
