# 田野正式文书与 Word 抬头纸 v1.2.0

## 何时使用
田野团队及获授权人员制作工作联系函、正式会议纪要、现场踏勘报告的 Word 文件时，使用 `assets/tianye_letterhead_v03.docx`。其他机构使用自己的抬头。微信工作回复直接提供可发送文字。合同、服务书、策略提案等遵循用户当次指定的文种和模板。

用户已给 Word 文件时优先在副本中编辑，检查其是否已带抬头，避免重复添加。抬头只提供品牌和版式，不提供项目事实、合同依据、签章或签发授权。新项目文件另存，不覆盖技能中的模板。

## 先理清事情，再形成文件
从同事给出的微信、口述、会议记录和现有文件提取已知事实。宽泛需求通常先问最影响成稿的1–3件事，材料齐全直接工作。用户不知道的非关键字段先用 `[待确认]` 留位。对内追问的细节不全部搬进对外文件。

工作联系函核对对象、事由、既有确认及版本、本次请求、期望反馈时间与方式、收到不同回复后的安排、附件与落款。表达礼貌、克制，请求具体，给对方明确的回应办法。期限区分合同约定与我方期望，不自行设定沉默即同意、违约责任或追加费率。

会议纪要区分实际讨论、已确认决定和待确认事项，行动项写清已确定的责任人与时限。现场踏勘报告区分看到、测到、听到及推断的内容，记录位置、照片或图纸依据和待补测事项。无人承担或未约定时间的事项保留待确认，不替相关方接受任务。

## 已确认版式
使用随包模板继承 A4 尺寸、21毫米左右页边距及固定页眉页脚。每页重复绿色标志、横条、联系方式和二维码，保持图片比例。

| 内容 | 设置 |
|---|---|
| 主标题 | MiSans 粗体14磅，居中 |
| 一级标题 | MiSans 粗体12磅 |
| 二级标题 | MiSans 粗体11磅 |
| 正文、落款、附件 | MiSans 常规11磅，正文固定18磅行距 |
| 联系方式 | MiSans 9磅 |
| 正文颜色 | 黑字白底，正文表格用黑白或灰阶 |
| 页眉页脚 | 保留品牌色，页码用黑色 |
| 页码 | 单页隐藏，多页从首页起居中显示“第1页／共2页” |

页码由 IF、PAGE、NUMPAGES 动态域组成，保留打开时请求更新域的设置。生成后重新分页、更新正文及各节页脚域，再导出检查。WPS可能在保存时移除打开更新设置，保存后应复核并恢复。条件域在不同客户端中的即时刷新行为存在差异；页数变动后必须检查打印预览，必要时选中页脚页码按F9。只在已实际测试的客户端上声称验证通过。

正文保持可编辑，使用 Title、Heading 1、Heading 2 和 Normal 样式。表格可跨页时重复表头，避免拆开落款及签署区域；不为凑页缩小字号。长表格或大图应调整布局，超出固定样式的调整说明给用户。

## 工具入口
Windows下先运行 `scripts/font_preflight.ps1 -Mode Check`。首次缺字时按 `references/font_setup.md` 执行部署，检查通过后再制作正式版。字体状态不足时可以先出内容草稿，但明确尚未完成字体和排版验证。

生成时使用 `scripts/build_word.py --input <UTF-8 JSON> --output <新文件.docx>`。输入格式见 `templates/document_input.example.json`，将已确认正文映射到段落和样式；脚本不负责补项目事实。已有规范正文可用 python-docx 或兼容OOXML工具编辑模板副本，同时保留品牌资源与动态域。

Windows本地可执行 `scripts/render_word.ps1 -InputPath <新文件.docx> -OutputDirectory <检查目录>`。脚本检查字体，识别Word接口实际宿主，处理工作副本、更新域并导出PDF，输出渲染记录。安装脚本支持在Windows PowerShell5.1执行；文书生成需要Python3及python-docx，PDF自动检查需要pdfplumber。缺少组件时报告缺口，利用现有工具继续可完成的部分，不谎称已生成或验证。

## 发出前检查
先核事实、图号版本、金额、时间、依据和附件，再检查对象、请求与反馈方式。正式文件所有页逐页渲染检查。对照PDF中的实际字体，确认正文黑白、页眉页脚完整、页码数量及位置正确、没有重叠和缺字。可用 `scripts/verify_document.py <docx> --pdf <pdf>` 执行结构和PDF检查，自动检查后仍需看每页图像。

交付Word文件并说明实际验证范围。签发由项目负责人完成。随包两个示范文件为虚构练习，不代表项目记录。
