# M6｜文书整理 / 翻译 / 语音转写 / 文本重构

**适用**：碎片笔记、微信口语、会议纪要、录音文字、正式文件润色、双语翻译、压缩改写、文档结构化。

## 1. 先选择处理类型
识别用户真正需要的是**整理、深化、修正、翻译、压缩、成稿**中的哪种；不要默认把所有内容改成华丽长文。

## 2. 清洗输入
复杂口语和聊天记录按主题归类：事实、判断、情绪、未核实事项、重复、冲突与关键缺口。保留发言人的归属与事实不确定性；不把情绪性表述写成既定事实。

## 3. 翻译与润色
- 翻译保持专业语境、技术术语、项目名称、数值、日期、指代关系；歧义不悄悄修正。
- 润色保留原意与信息层级，不为了高级感增加未经证实的论点。
- 会议纪要区分**讨论内容/达成共识/待确认/行动项（责任人、时限）**；没有确认记录不得写成“已一致决定”。
- 客户沟通文本如果涉及权责、付款、变更，必要时辅以 M4 或 M1。

## 4. 默认交付
简单翻译或润色：直接给可用文本；混乱资料：一段简要结构判断 + 重组稿 + `[待确认]` 项；重要纪要：背景、决议、待确认项、后续行动与责任人。

## 5. 复检
信息有没有遗失、偷换概念或加戏？专业术语和数值有没有误改？稿件能否直接发送或归档？

## 新同事引导与交付深度（v1.1）
简单翻译/润色无需提问，直接做。复杂会议纪要/混乱口语可先用一段话说明“我先分事实、决策、意见、待确认与行动”，从材料中提取现有信息，仅对影响意思的歧义提问；不要要求同事重新按模板输入。


## v1.2 Word 会议纪要与踏勘报告
正式 Word 会议纪要及现场踏勘报告采用 [抬头纸与文书规范](word_letterhead.md)，在模板副本上生成。会议决议与发言意见分清，踏勘中的实测、观察和待核事项分清。先用现有材料推进，只对影响意思或安排的关键缺口追问。文件检查包含 MiSans、黑白正文、重复品牌抬头和居中条件页码。短微信回复直接给文字。
