# M4｜商务沟通 / 催款 / 邮件 / 工作联系函

**适用**：支付申请、尾款催付、进度协调、图纸/平面确认、施工技术边界、变更澄清、客户安抚、邮件、正式函件。

## 1. 判断沟通位置
明确对方情绪、立场与决策权；我方目标和底线；关系优先还是边界优先；是否需保留证据或为升级沟通留余地。分开写“事实”“合同依据”“本次申请”“截止时间”“后续安排”。

## 2. 写之前先看风险
- 是否太软，以至于丧失付款、确认或工作范围边界？
- 是否太硬，形成不必要的关系冲突？
- 时间表、金额、付款条件、图纸版本和附件是否足够明确？
- 把电话讨论结果写成“双方已书面确认”了吗？
- 是否把施工单位的单方主张写成合规结论？

## 3. 推荐函件结构
标题（项目 + 主题 + 函件种类）→ 称谓 → 项目及合同背景 → 已发生且可证明的事实 → 核心问题/风险与双方界面 → 需要对方确认/支付/指定责任人的具体事项 → 反馈期限及下一步安排 → 附件/落款/日期。

## 4. 表达要求
专业、克制、简洁、有证据，不阴阳怪气。该说的金额、节点、边界说清楚；不过度申诉个人牺牲，也不通过道德压力代替合同依据。

## 5. 输出选择
- 简单短信/邮件：只给可发送稿，不强制双版本。
- 商务敏感：默认更柔和/更坚定两版（或先给推荐稿，标注可升级句式），并说明适用情况。
- 正式函件：正文 + 附件清单 + 必要待核事项 + 简短风险复检。
- 催款：写明合同、具体应付金额、应付节点、已履行事项、付款请求与期限；无法核实时保留占位符。
- 附带确认框可供签收，但未签收不得擅自称已经确认。

## 6. 额外提醒
“逾期不回复视为同意”、特定追加费率、技术免审结论都不能随意作为事实或法律定论；应回到原合同及真实通知程序。

可参考 `templates/T2-设计变更确认函.md` 和 `templates/T3-追加设计费用申请函.md`。

## 新同事引导与交付深度（v1.1）
用户只说“帮我写工作联系函”时，先问函件目的（确认/催款/变更/责任界面等）、事实及可核对证据、希望对方采取的动作与期限，最多3问；适当解释为什么要问（函件不是表态，而是推进下一步）。对需要专业核验的责任争议优先澄清界面，不把单方说法当定论。对外正式稿需要收件人、请求、附件和落款；不知道就以 `[待确认]` 留位。用户不清楚语气时默认“友好但明确”。


## v1.2 正式文书输出
工作联系函需要 Word 文件时，读取 [抬头纸与文书规范](word_letterhead.md)，从模板副本生成完整文件，并检查字体、条件页码和附件。微信回复使用实际语境写成可发送文字。客户催图时，引导确认客户急用的具体内容、既有约期和团队可交付范围，以及付款节点和发图前置约定；到期应付与到账才能发图分别核实。尊重客户的急迫与既有沟通，说明具体安排，不自行承诺明天交图。
