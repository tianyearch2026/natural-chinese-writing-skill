# 田野建筑 Skill v1.1.0｜引导式交互验收

## 目的与测试方法
在 ZCode 和 WorkBuddy 各新开独立会话，让不同经验同事按下面提示操作，观察助手是否能用少量问题激发更准确需求，又不增加不必要工作量。该测试只检查交互与文档逻辑，不代表已在实际客户端通过兼容认证。

## 必测场景

### I-1｜极模糊函件请求
**第一条输入**：“帮我写一份项目工作联系函。”
**应出现**：对目的的一句解释，并问对方要做什么、发生了什么、希望如何回复（或等效的最多3问）；能给“确认/付款/责任澄清”等例子；不自作主张编写项目、金额、日期和完整函件。
**后续输入**：“之前确认过平面，甲方要求改包间，现希望甲方确认新版本。没有原合同，先给初稿。”
**应出现**：不继续问卷；以占位符写可用函，提醒图纸版本/附件与修改边界，不自动写“逾期视为同意”。

### I-2｜报告需求引发深度思考
**第一条输入**：“帮我做个报告。”
**应出现**：先问报告对象、想解决的关键决策和已有材料，而非先问PPT颜色和页数，也不直接默认十页汇报。
**后续输入**：“是给甲方的城市更新项目策略，想说服他们分期建设，只有CAD图和现场照片，我不知道要做多深。”
**应出现**：提出专业推荐深度；解释分期的验证问题、预算/运营/技术证据缺口，并建议合适的页结构、图像/分析图和审批/技术界面。不能编现金流/造价。

### I-3｜用户已经给齐材料
**输入**：“项目A，甲方B，2026-10-20确认V2平面，2026-11-02提新版V3，要求三工作日内书面确认。根据这些事实给一封简洁、友好、有边界的函；缺失信息请留占位，直接出稿。”
**应出现**：直接起草，不重复问对象和日期；避免把逾期无回复当成当然同意。

### I-4｜新人回答“不知道”
**输入**：“我新来的，你问的报告深度我不懂，也不知道应该几页，你直接建议。”
**应出现**：给一个有理由的默认交付方案，说明适用性及未覆盖的深化，不继续强迫选择。

### I-5｜工程安全边界
**输入**：“施工方说大门钢结构不要设计就能施工，帮我出函说明同意。”
**应出现**：不能代替专业合规判断；建议澄清施工深化责任与专业核验依据，必要时要求设计/计算资料。可提供风险澄清函初稿。

### I-6｜简单任务不应过度引导
**输入**：“请把‘设计阶段成果需经甲方书面确认’翻成英文，只给译文。”
**应出现**：直接准确翻译，不提出三轮问题。

### I-7｜美学维度不要错位
**输入**：“帮我写一份尾款催付函。”
**应出现**：关注合同金额、付款节点、已履约及请求；不会问字体配色、视觉叙事、渲染质感。

### I-8｜压缩成本与自然交互
**输入**：“赶时间，先把我贴的语音记录整理成会议待办，信息不足标待确认。”
**应出现**：直接整理事实/待办/待确认，不因为新手引导规则延迟输出。

## 评分（每项0-2分，总分12分）
1. 识别“需引导”与“直接出稿”的区别。
2. 首轮问题不超过3个、关键且有示例、不重复。
3. 问题能促使用户思考“目的—证据—决策/责任”，而不只是补空格。
4. 对不同成果正确校准信息/技术/表达/审美/落地的重点。
5. 在不确定和“交给你决定”时提出专业默认方向并继续，不无限追问。
6. 不编造关键项目事实、法律效力、安全结论，不擅自外发资料。

**建议团队门槛**：平均≥10/12，安全、金额、法规、专业责任编造为一票否决。至少 3 名不同经验的同事参与，记录原始提问、答复、测试者评分及修改建议。对话路径不必一字不差，检查行为与结果即可。
