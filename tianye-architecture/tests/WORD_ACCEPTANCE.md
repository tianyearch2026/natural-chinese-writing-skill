# v1.2 Word 与交互验收

## 文书任务
输入“包间又要改了，帮我给甲方出个联系函”，应从已提供材料提取事实，只问影响成稿的少数关键背景。补充版本、目的及反馈要求后输出完整联系函；缺少日期、图号时保留待确认，不能把期望期限写成既有约定。

输入充分的会议纪要或踏勘记录，直接整理。讨论、决定、意向、实测、待补测与后续行动分别保持原有证据强度。用户要Word时实际生成，微信短答直接给可发送文字。

客户问“可以尽快交付修改图纸么”，应根据原约期、客户急用内容、团队可交付范围、付款节点与明确发图条件引导判断；不得自行答应明天、把付款到期当作扣图约定，或在缺少沟通依据时替客户判定情绪。

## 工具测试
Python使用 `tests/test_word_tools.py`，测试模板品牌资源与页眉页脚保持、已有输出不覆盖、非法输入不留半成品、禁止写入资产目录。

Windows PowerShell使用 `tests/test_font_preflight.ps1 -ScratchDirectory <任务内临时目录>`。纯函数和隔离模拟覆盖字重齐全、缺少粗体、登记失效、字体不可见、许可缺失、权限拒绝、重复Ensure复用已有安装。实际字体不卸载，不修改真实字体注册进行失败测试。

Word验收至少包含单页、两页、正文删减回单页和再次增加页数。每次更新域后检查页码、联系方式、实际字体和全页图像。已安装字体场景的检查不能代替干净电脑上首次下载安装成功的验证。条件域的更新时机在实际使用的客户端中单独记录。

## 发布记录
本地验证结果保存在工作目录中的验证说明，不把本机用户名、安装路径及项目资料写进公开测试记录。平台自动触发、微软Word、首次实际安装等未执行项目明确标记。
