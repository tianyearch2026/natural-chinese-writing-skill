# 田野建筑通用 Skill v1.1.0｜团队安装与使用

## 一句话说明
这是给田野建筑同事用的通用专业工作方法包：**一个 Skill、六个专业模块、无需 API Key、不带可执行脚本**。不同模型写作能力仍会不同，Skill 能统一工作要求但不能保证不同工具输出完全相同。

## 先检查压缩包
解压后应出现 `tianye-architecture/` 文件夹，内部**直接有** `SKILL.md`，并包含 `references/`、`templates/`、`tests/`。不要把 `SKILL.md` 单独拎出来安装，否则专业模块会丢失。

## ZCode（ZCode Agent）安装
1. 解压 ZIP。
2. 将整个 `tianye-architecture` 文件夹复制到用户技能目录：
   - macOS / Linux: `~/.zcode/skills/tianye-architecture/`
   - Windows：安装版本如支持类 Unix 用户目录，请在 ZCode「设置 → 技能」查看实际技能位置；不要机械照搬路径。
3. 在 ZCode 打开 **设置 → 技能**，点「刷新」并启用 `tianye-architecture`。
4. 在聊天框键入 `$tianye-architecture`，后接工作需求。例如：
   `$tianye-architecture 请审查附件合同里的服务范围与付款节点。`
5. 也可在「设置 → 技能」使用导入入口选择已解压的技能目录。若自动调用不稳定，先显式用 `$tianye-architecture`。

ZCode 官方说明：`https://zcode.z.ai/cn/docs/skill`。

## WorkBuddy 安装
1. 推荐优先通过 WorkBuddy 的「专家·技能·连接器 → 技能 → 添加技能/创建技能」或其开放平台支持的导入方式安装。
2. 如使用**上传 ZIP**方式，选择本 ZIP（根为一个 `tianye-architecture/` 文件夹，内有 `SKILL.md`）；这是其官方技能基础结构支持的形式。不同客户端版本入口可能变化。
3. 如使用本地工作区级技能发现机制，可将整个文件夹放入该工作区的 `.agents/skills/tianye-architecture/`，然后重启或刷新，并在已安装技能中核对。具体路径以用户所用版本实际设置为准。
4. 对话中主动选择/引用「田野建筑工作助手」，再描述任务。若 Skill 未自动触发，显式说“请调用田野建筑工作助手，并读取相应 M 模块”。

WorkBuddy 开放平台技能说明：`https://open.workbuddy.cn/docs/skill`。

## 非上述两平台的兼容用法
只要工具支持 Agent Skills 的文件夹格式，可尝试导入此目录。若工具不自动识别 `SKILL.md`，把该文件内容设为“自定义指令”，并确保可访问 `references/` 中的相关模块；这种手动用法**不保证自动按需加载**。

## 新人第一次使用：不需要学 Prompt，也不用记 M1–M6

直接像找同事一样说：

> “帮我写一个项目工作联系函。”
>
> “我要做个项目报告，但不知道怎样组织内容，请引导我。”
>
> “有个业主想增加设计范围，我不知道该怎样谈。”

Skill 应先用通俗、专业的方式问**1–3 个关键问题**，让你说清读者、目的和事实；必要时再问一次交付深度和关键边界，然后形成正式成果。**无需先填复杂表格**。

你可以用这些简单回复控制节奏：
- “我不知道，你先推荐一个合理的做法。”——助手应给专业默认方案并继续。
- “先做内部讨论稿。”——助手会降低排版和签发要求，突出问题、判断与选项。
- “要给甲方正式汇报，重点做专业深度和图文表达。”——助手应校准信息、技术、表达、审美、落地五层。
- “时间紧，直接出稿，不要提问。”——助手应立即起草，不确定处以 `[待确认]` 留位。
- “先只帮我判断，不用出最终文件。”——助手应切换为诊断和协作模式。

**重要提醒**：Skill 能辅助构思、梳理和草拟，不能代替项目负责人对事实、责任、技术安全及合同条款的审核。哪怕模型说“已完成”，对外签发前也必须有人复核。

关于复杂交付，可参看 `references/DELIVERABLE_QUALITY.md`；示范对话见 `examples/NEW_USER_DIALOGUES.md`；交互验收见 `tests/INTERACTIVE_TEST_CASES.md`。

## 团队日常怎么使用
- 平常只需说任务，例如“帮我写项目平面确认函”；可主动指定 “M4”。
- 附上**当期项目**合同、图纸版本和必要事实，不能以通用 Skill 代替项目基础资料。
- 用于对外正式文件时，请负责同事核实合同与金额、甲乙方、时限、专业判断、发函附件及发送渠道。
- 重要方案应由项目负责人审核反方质疑；工程安全、专业深化和法律争议需要相应专业人员签字把关。

## 成本控制
- 当前包只设一个被系统发现的 Skill，避免六个技能同时抢上下文。
- 总入口 `SKILL.md` 是简版路由；一次只读取 `CORE.md` 和任务相关模块，其余不加载。
- 尽量一次性给出项目目标、必要附件与预计成果格式，减少反复问答。
- 真正消耗成本的是模型调用、长附件和复杂生成任务；本 Skill 自身不收费，但不能承诺第三方产品调用免费。

## 使用前测试
查看 `tests/TEST_CASES.md`，建议用同一段简短要求在 ZCode 和 WorkBuddy 各测试至少 3 题。除原有测试外，另用 `tests/INTERACTIVE_TEST_CASES.md` 测试模糊需求的引导能力。重点看首轮是否少问关键问题、信息充分时是否立即出稿、是否能帮助同事定义交付质量，以及是否遵守事实和技术责任边界。

## 版本与内部分享
版本 `1.1.0`，面向田野建筑内部使用。不要未经事务所同意公开发布、上传真实客户材料或向外部服务商复制敏感信息。更新时统一替换文件夹，保持同事版本一致；每次改规则前先检查 3 个典型测试题是否退化。
