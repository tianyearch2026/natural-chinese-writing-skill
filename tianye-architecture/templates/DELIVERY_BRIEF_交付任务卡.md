# 田野建筑 · 交付任务卡（必要时内部使用，不要每次发给用户填写）

**使用方式**：在关键任务完成一到两轮引导后，由助手**自动整理**成一段简短的任务确认，用户无需逐项填写；仅当理解存在重大分歧时请用户核对。小任务不要展示。

## 任务定义
- 任务类型 / 关联模块：[助手判断]
- 当前对象与用途：[已知 / 待确认]
- 希望促成的一个关键动作或决策：[已知 / 待确认]
- 本项目现有材料、证据、图纸/合同版本：[已知 / 待确认]
- 最重要的项目制约/商务边界：[已知 / 待确认]

## 交付深度（由助手推荐，不让用户做复杂选择）
- 建议深度：[快速讨论 / 内部决策 / 对外正式 / 专业协同]
- 信息层：[需说明事实、版本、来源、缺口]
- 技术层：[本任务适用的深度与需复核内容；不适用则写“不额外要求”]
- 表达层：[受众、目标、语气、说服逻辑]
- 审美层：[媒介、图文组织、图像、页面气质；如不适用则略]
- 落地层：[输出文件/格式、行动主体、节点、待确认清单]

## 可以直接开始吗？
- **是**：无需再问，直接交付。
- **部分可以**：先出带 `[待确认]` 的成果，列签发/深化前必须补的 1–3 项。
- **不能安全下结论**：指出阻塞事实和专业责任人，先完成可行的风险/沟通初稿。
